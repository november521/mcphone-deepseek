## 那个 bug 长什么样

本体 1.9.3 加了「设置 → 界面大小」：能把整部手机放大到 300%。放大之后打开这个 App，你会看到**消息被切掉一块**——不是没画出来，是被裁在一个位置和大小都不对的框里。会话列表和设置列表同样。**界面大小停在 100% 时一切正常**，所以它只会在你调过大小之后出现。

## 为什么会这样

整部手机是套在一层缩放里画的，而这个 App 的三处裁剪调的是原版的 `GuiGraphics.enableScissor`——那句收的是**窗口坐标**，并且**完全不看那层缩放**。我们交进去的是没缩放的手机坐标，于是内容跟着放大了、裁剪框还停在 100% 时的位置和大小上。

这不是本体的锅，也不是"忘了适配"：本体那一侧（鼠标坐标、页面拿到的位置与尺寸）早就替附属换算好了，唯独裁剪本体够不着——附属手里握着的是真正的 `GuiGraphics`，调下去的那一刻本体不在场。

## 怎么修的

三处全部改用本体 1.9.3 新加的 `PhoneCanvas.clipped(x, y, w, h, () -> ...)`。它把矩形过一遍当前的变换矩阵，缩放几层都对；而且自带 `try/finally`，中间抛异常也会把裁剪收回去——原来那种写法一旦在开着裁剪时抛异常，整个游戏界面都会被切在那个框里，还会跨帧留着。

**写附属的人注意**：如果你的页面里有 `canvas.graphics().enableScissor(...)`，它在玩家把界面调离 100% 时就是这个毛病，而你在 100% 下怎么测都是好的。换成 `canvas.clipped(...)`，本体那边的 `docs/addon-api.md` 与 `docs/AddonApiExamples.java` 里有现成样板。
