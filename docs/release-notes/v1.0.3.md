# MCphone DeepSeek v1.0.3

**只有一件事：前置从 MCphone 1.8.18 提到 1.8.19。** 功能一处没动，界面一个像素没改。

**运行环境：** Minecraft 1.21.1 · NeoForge 21.1.200 或更高 · **只装客户端**
**前置：** [MCphone](https://github.com/november521/mcphone) **1.8.19 或更高**（上一版是 1.8.18）

> **⚠️ 本体没换成 1.8.19 的话，这一版不会加载。** 不是"能跑但有问题"——NeoForge 会在加载阶段就按 `versionRange` 把它挡下来，给你一个缺前置的报错页。要么本体一起升到 [1.8.19](https://github.com/november521/mcphone/releases/tag/v1.8.19)，要么留在 1.0.2 别升。

**从 1.0.2 升级：** 换掉 jar，同时把本体换成 1.8.19。API Key、服务地址、模型、所有对话记录全部原样保留——这一版没动任何存储格式，`config/mcphone_deepseek/` 下那两个文件一个字节都不会被碰。

---

## 为什么要把下限提上去

MCphone 1.8.18 有一个会让**整部手机一片空白**的 bug：打开手机，主屏一个 App 图标都没有，包括本体自带的那十几个。

成因在本体的 SPI 扫描：它用了单参的 `ServiceLoader.load(service)`，那个重载取的是**当前线程的 context classloader**。而这次扫描由 `FMLClientSetupEvent` 触发，跑在并行模组派发的 ForkJoinPool worker 上——那种 worker 的 TCCL 是从"碰巧创建它的那个线程"复制来的，而 worker 是按需惰性创建的，所以每次启动都可能不一样。赶上一个看不见 `META-INF/services` 的，这一轮**一个服务都扫不到，而且不报错**。

所以它是随机的：同一台机器、同一套模组，这次开正常，下次开就空了。1.8.18 那一版扫空之后还会落锁，整局不再重扫，重进世界都治不好，只能重启游戏。

**这条对附属格外致命。** 丢的是全部 App，但玩家的第一反应必然是"我刚装的这个 DeepSeek 附属把手机搞坏了"——毕竟它是最后装进去的那个。本体自带的 App 一起消失这件事，从游戏里根本看不出来。

本体 v1.8.19 已经修好（把类加载器显式传进去，并且扫空不再落锁、最多重试两次）。附属这边能做的就是把下限提上去，别让玩家有机会踩到。

## 没有放宽的余地

版本下限和编译对着的 jar 始终是同一个数（`gradle.properties` 里的 `mcphone_version`）。附属宣称支持一个从没编译验证过的本体旧版，只会把 `NoSuchMethodError` 留给玩家。这一版把 `libs/` 里的 jar 换成了 1.8.19，两个数一起动。

## 给服主与整合包作者

**服主：** 什么都不用做，这个模组是纯客户端的。

**整合包作者：** 前置最低版本变了，包里的 MCphone 必须是 1.8.19 或更高。顺带一提，1.8.18 那个 bug 在整合包里更容易撞上——模组越多、并行加载的 worker 越多，抽中一个坏 TCCL 的机会就越大。
